# 法条文件格式规范

## 文件命名

`<法律名>-<编章>.txt` 或 `<法律名>.txt`

例：`民法典-侵权责任编.txt`、`刑法.txt`

## 文件结构

```
#META
法名: 中华人民共和国民法典
编章: 第七编 侵权责任（如无编章可省略）
颁布日期: 2020-05-28
施行日期: 2021-01-01
最后修订: 2020-05-28
状态: 现行有效 | 已修订 | 已废止
取代: 被取代的法律名称（已废止/已修订时填写）
#END

第X条
条文内容（可跨多行，以空行分隔下一条）

第Y条
条文内容
```

## 元数据字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| 法名 | ✅ | 法律全称 |
| 编章 | 否 | 民法典分编时填写 |
| 颁布日期 | ✅ | YYYY-MM-DD |
| 施行日期 | ✅ | YYYY-MM-DD |
| 最后修订 | ✅ | 最近一次修订的日期 |
| 状态 | ✅ | 现行有效 / 已修订 / 已废止 |
| 取代 | 否 | 如该法取代了旧法，写明旧法名称 |

## 条文格式

- `第X条` 顶格写，条文内容紧跟其后
- 条文可跨多行
- 条文之间用空行分隔
- `#META...#END` 块内的内容不会被当作条文检索

## 程序读取逻辑

1. 读取文件 → 解析 `#META...#END` 获取元数据
2. **检索前先把 `#META...#END` 整块切掉**，再拿剩下的正文用 `全文.find("第X条")` 定位条文
   （`verify_laws._读取法条库`）。这一条以前只是这里写着、代码没做：2026-09-20 补《劳动法》时
   在 `核对:` 里写了"第44条「工作」…"，于是引用《劳动法》第44条**在这段来源说明里命中**，
   返回给用户看的"条文"其实是互校记录 —— 假绿灯。现在有 `test_检索范围不含META` 钉着
3. 前端展示时标注状态颜色：绿色=现行有效，黄色=已修订，红色=已废止

## 正文从哪来（2026-09-20 起）

⚠️ 定位是 `find("第X条")`，所以**库文件本身出错 = 对真实法条亮红牌**。
2026-09-20 第一次体检发现：11 个文件里 9 条正文整条缺失、3 处标题下装的是上一条的
尾巴（跨引用"本法第七十五条另有规定的除外"被当成了新条的标题，于是从那里断开）、
41 处条号还粘在上一条正文里。修法不是手打补全 —— 手打就是在给防幻觉工具喂幻觉。

现在的规矩：
- **两份以上 `.gov.cn` 转载页逐条互校**，两源一致才收；只在标点全半角上不同不算分歧，
  "第五项"与"第(五)项"这种编号样式差异也不算
- 分歧分两种，处理方式不一样：
  - **尾部页脚**（扫一扫 / 主办单位 / 附件 / 打印）⇒ 只保留两源一致的前缀
  - **正文实质分歧**（条文里的跨引用号不同等）⇒ **整条不收**，去查更权威的来源。
    截半条写进库比缺一条更糟 —— 缺一条只是校验不了，半条会带着"可验证"的绿灯骗人
- 文件的 `#META` 里必须写 `来源:`（两个 URL）和 `核对:`（日期 + 分歧说明）
- 改完跑 `python3 scripts/check_law_library.py`，它查缺号 / 错配 / 埋着的标题，
  有问题就非零退出

⚠️ "两份以上"要的是**独立**的两份。同一篇《2021年最新〈著作权法〉全文解读》被三个
城市各自转载，只算一份 —— 它们在第41条里一起把"第三十九条"写成了"第三十八条"。
标题一字不差的多个页面，先当成同一份稿子看。

## 国家法律法规数据库（flk.npc.gov.cn）怎么取

它是 SPA，但接口能直接打，2026-09-20 用它补了劳动法两部：

1. `POST /law-search/search/list`，JSON 体形如
   `{"searchRange":1,"sxrq":[],"gbrq":[],"searchType":2,"sxx":[],"gbrqYear":[],
     "flfgCodeId":[],"zdjgCodeId":[],"searchContent":"中华人民共和国劳动法",
     "orderByParam":{"order":"-1","sort":""},"pageNum":1,"pageSize":20}`
   —— 少一个字段就 500「系统异常」，猜不出来，得在浏览器里挂 XHR 抓一份真载荷再改关键词。
   返回是 `{total, rows:[…]}`（不是 `data.list`），`title` 里带 `<em>` 高亮标签要先剥，
   `sxx`：1=已废止 2=已修改 3=现行有效。
2. `GET /law-search/search/flfgDetails?bbbs=<id>` → `data.ossFile.ossWordOfdPath`
3. `GET /law-search/amazonFile/previewLink?filePath=<那个 ofd 路径>` → `data.url`，
   里面 `file=` 后面那串是签名后的内部地址（会过期，拿到就用）
4. `GET https://flkofd.npc.gov.cn/reader/text?file=<那串>&_i=<页码>` → 该页文本层
   （`areas[].lines[].chars[].char`，带坐标，按 y、x 排序拼回行）。**跨域，浏览器里取不到，
   要在脚本里走。**

两个坑：页码行是 `－2－` 这种**全角**减号，清洗时按 ASCII 减号去猜会漏，
于是页码数字被粘进正文；`ossWordPath`（.docx）那个 previewLink 只发 OFD 预览，
拿回来是 HTML，别指望它给 Word。

待补而未补：《著作权法》卡在第41条的跨引用分歧（39 vs 38，转载页之间无法裁决），
需要国家法律法规数据库或人大公报版本；《反不正当竞争法》《合伙企业法》《电子签名法》
《侵权责任法》（已废止，仍有人引）见 `missing_laws.txt`。
